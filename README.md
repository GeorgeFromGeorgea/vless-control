# VLESS Control

Проект для управления Xray/VLESS через административного Telegram-бота.

> **Стадия разработки.** Есть реестр пользователей и профилей, Telegram-бот, проверка состояния сервера и синхронизация UUID с выбранными существующими VLESS-inbound. Это пока не установщик VPN с нуля: Xray, DNS, TLS-сертификаты, firewall и inbound-порты автоматически не устанавливаются и не настраиваются. Работу через конкретного мобильного оператора гарантировать нельзя.

**Целевые ОС:** Ubuntu Server 22.04/24.04, Debian 12. **Python:** 3.11+.

## Что уже умеет

- Создавать пользователя с индивидуальным UUID.
- Назначать несколько профилей подключения одному пользователю — с единым UUID для fallback-ссылок.
- Создавать профиль через пошаговую форму Telegram с проверкой полей.
- Показывать администратору VLESS-ссылки в личном чате с ботом.
- Деактивировать запись пользователя после подтверждения.
- Синхронизировать UUID с указанными существующими Xray-inbound; dry-run по умолчанию.
- Создать backup перед применением, проверить конфиг Xray, заменить его атомарно и попытаться восстановить прежнюю конфигурацию при сбое.
- Выполнять read-only preflight: ОС, Xray, конфиг, дисковое место, память, слушающие порты и статусы Xray/nginx.

## Ограничения

- Нет установки/удаления Xray и настройки firewall, DNS, TLS.
- Профили в боте описывают уже существующие inbound и должны совпадать с Xray `inbound.tag`.
- Sync изменяет список клиентов в управляемых inbound. Не используйте inbound, которым управляет другая панель, без проверки владения списком.
- Деактивация в базе не отзывает ключ из работающего Xray, пока не выполнена синхронизация.
- Нет срока действия ключей, лимитов трафика, пользовательской панели и интеграционных тестов на реальных VM.
- Проверка порта сервера не определяет, работает ли соединение у конкретного абонента по Wi-Fi или мобильной сети.

## Установка приложения

```bash
git clone https://github.com/GeorgeFromGeorgea/vless-control.git
cd vless-control
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
cp .env.example .env
chmod 600 .env
```

Настройте `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=ТОКЕН_ОТ_BOTFATHER
TELEGRAM_ADMIN_IDS=123456789
DATABASE_PATH=data/vless-control.sqlite3
XRAY_CONFIG_PATH=/usr/local/etc/xray/config.json
XRAY_BINARY=/usr/local/bin/xray
XRAY_SERVICE=xray
```

Приложение не загружает `.env` автоматически. Экспортируйте настройки перед запуском:

```bash
set -a; . ./.env; set +a
```

Не публикуйте токен, файл `.env`, базу SQLite, Xray-конфиг, приватные ключи и VLESS-ссылки.

## Read-only проверка сервера

Проверить сервер, ничего на нём не меняя:

```bash
.venv/bin/vless-control-preflight
```

Для нестандартного пути к конфигу:

```bash
.venv/bin/vless-control-preflight --config /путь/к/config.json
```

Команда выводит JSON с ОС и версией, Python, архитектурой, наличием Xray и конфига, RAM, свободным диском, слушающими портами (в т.ч. 80/443/8443/2053/10001) и статусами Xray/nginx. Она не устанавливает пакеты, не пишет файлы, не меняет firewall и не перезапускает службы. Для неподдерживаемой ОС завершается кодом `2`.

> Это только сбор сведений. Наличие свободного порта или активной службы не доказывает доступность с телефона или через мобильного оператора.

## Запуск Telegram-бота

Создайте отдельного бота в BotFather. Укажите его токен и свой числовой Telegram ID в `.env`, затем выполните:

```bash
set -a; . ./.env; set +a
.venv/bin/vless-control-bot
```

Откройте бота в личном чате и отправьте `/start`. Бот не запустится без токена и хотя бы одного числового ID администратора. Команды из групп не выполняются.

### Кнопки

- **Пользователи** — список пользователей без UUID.
- **Новый ключ** — создаёт запись пользователя и индивидуальный UUID.
- **Профили** — показывает профили.
- **➕ Профиль** — мастер создания профиля.
- **Назначить профили** — выбирает пользователя и профили/fallback-порты.
- **Выдать ссылки** — показывает ссылки администратору в приватном чате.
- **Отмена** — отменяет незавершённый ввод.

Ссылки — это учётные данные. В текущей версии бот не отправляет их конечному пользователю: администратор должен передать ссылку лично.

### Команды

- `/users`
- `/new_user ИМЯ`
- `/profiles`
- `/assign USER_ID PROFILE_ID[,PROFILE_ID]`
- `/links USER_ID`
- `/revoke USER_ID` — запрос подтверждения
- `/revoke confirm USER_ID` — подтвердить деактивацию

## Создание профиля

В мастере Telegram по очереди задаются имя профиля, адрес сервера, порт, защита, транспорт и нужные для выбранного режима параметры:

- REALITY: TCP, SNI, клиентский публичный ключ и short ID;
- TLS: SNI;
- WS: путь, начинающийся с `/`.

Имя профиля должно совпадать с `tag` уже настроенного VLESS-inbound Xray. Мастер не создаёт этот inbound и не открывает порт в firewall. Проверьте соответствие параметров серверной конфигурации до выдачи ссылки.

## Установщик Xray

В репозитории появился **консервативный opt-in установщик**. Он не скачивает случайные файлы, требует локальный архив официального релиза и SHA-256 из официальных checksum. По умолчанию это только план; даже после `--apply` он не включает и не запускает службу и не создаёт рабочий VLESS-конфиг.

### Подготовка параметров установки и `.env`

Перед установкой на сервер подготовьте:

1. **Telegram-бота и токен:** откройте `@BotFather` в Telegram, выполните `/newbot`, задайте имя и username, затем сохраните выданный токен. Токен нельзя публиковать или отправлять в GitHub.
2. **Числовой Telegram ID администратора:** получите свой numeric ID через проверенный Telegram-инструмент/бот или из уже используемой админ-системы. Нужен именно ID, а не `@username`.
3. **Пути Xray:** обычно используются значения по умолчанию `/usr/local/etc/xray/config.json`, `/usr/local/bin/xray` и служба `xray`. Если на сервере другая установка, заранее уточните реальные пути.
4. **Путь базы:** по умолчанию `data/vless-control.sqlite3` внутри проекта.

Установщик может запросить эти значения интерактивно и создать `.env` непосредственно на сервере:

```bash
.venv/bin/vless-control-install --configure-env --env .env
```

Токен вводится скрыто и не выводится. Файл создаётся с правами `600`. Существующий `.env` установщик не перезаписывает без `--force-env` и отдельного подтверждения. После создания проверьте только наличие файла и права, не выводя его содержимое.
- **Официальный checksum:** на странице официальных релизов Xray скачайте архив под архитектуру сервера и файл checksum тем же способом.
- Передайте на сервер только архив и перепишите ожидаемый SHA-256 из официального файла.
- Выполните read-only preflight.

```bash
.venv/bin/vless-control-preflight
```

### Dry-run установщика

```bash
.venv/bin/vless-control-install \\
  --artifact /root/xray-linux-64.tar.gz \\
  --sha256 SHA256_ИЗ_ОФИЦИАЛЬНОГО_CHECKSUM
```

Проверяются поддерживаемая ОС, SHA-256, наличие существующего Xray и конфигурации. Если Xray или конфиг уже есть, замена блокируется без явного `--replace-existing`.

### Явная установка файлов

```bash
sudo .venv/bin/vless-control-install \\
  --artifact /root/xray-linux-64.tar.gz \\
  --sha256 SHA256_ИЗ_ОФИЦИАЛЬНОГО_CHECKSUM \\
  --apply
```

Установка:

- копирует проверенный бинарник в `/usr/local/bin/xray`;
- создаёт unit `/etc/systemd/system/vless-control-xray.service`;
- проверяет запуск `xray version`;
- не создаёт `config.json` автоматически;
- не вызывает `systemctl enable`, `start` или `restart`.

Для существующей установки требуется дополнительное явное решение оператора:

```bash
sudo .venv/bin/vless-control-install \\
  --artifact /root/xray-linux-64.tar.gz \\
  --sha256 SHA256_ИЗ_ОФИЦИАЛЬНОГО_CHECKSUM \\
  --replace-existing --apply
```

При замене создаётся backup в `/root/vless-control-backups`. Не используйте этот режим, пока не проверили, что текущую установку не обслуживает другая панель.

После установки бинарника конфигурацию нужно создать отдельно и проверить:

```bash
sudo /usr/local/bin/xray run -test -config /usr/local/etc/xray/config.json
```

Только после проверки конфига, портов и резервной копии оператор может вручную установить/запустить unit. Проект пока намеренно не выполняет это автоматически.

> Архив должен быть скачан из официального источника Xray. Никогда не подставляйте checksum, полученный из непроверенного чата или стороннего сайта.


Синхронизация работает только с существующим конфигом. Названия активных профилей используются как inbound-теги; назначенные активным пользователям UUID помещаются в список клиентов выбранных inbound. Активный профиль без пользователей синхронизируется с пустым списком клиентов.

### 1. Dry-run (по умолчанию)

Запускайте на сервере, где доступны база проекта и Xray-конфиг:

```bash
set -a; . ./.env; set +a
.venv/bin/vless-control-sync > /tmp/vless-control-candidate.json
```

Команда не меняет конфиг и не перезапускает службу. Проверьте результат вручную. Кандидат может содержать чувствительную конфигурацию — храните файл приватно и не загружайте в GitHub.

### 2. Явное применение

Перед применением убедитесь, что профильные inbound предназначены для управления этим проектом и список их клиентов не поддерживается другой панелью. Сделайте независимую резервную копию конфигурации. Затем:

```bash
.venv/bin/vless-control-sync --apply
```

При применении программа проверяет конфиг через `xray run -test -config`, создаёт и проверяет резервную копию рядом с конфигом, атомарно заменяет файл, повторно валидирует и перезапускает службу из `XRAY_SERVICE` (по умолчанию `xray`). При ошибке восстанавливает прежнее содержимое и пытается перезапустить Xray со старым конфигом. После выполнения проверьте backup, статус службы и журнал.

Без перезапуска службы (только для осознанного ручного обслуживания):

```bash
.venv/bin/vless-control-sync --apply --no-restart
```

Это не обновит конфигурацию, уже загруженную процессом Xray, до последующего безопасного reload/restart.

Для записи конфига и рестарта нужны системные права. Пока нет ограниченного привилегированного helper, поэтому не запускайте Telegram-бот целиком от root ради sync. Применение на рабочем сервере предварительно проверьте на тестовой VM.

## Тесты

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m compileall -q vless_control tests
```

Тесты покрывают реестр, профили, генерацию ссылок, dry-run и rollback-sync, валидацию мастера и read-only preflight. Для Xray/systemd применяются моки и временные файлы. Тесты не доказывают работу настоящего Xray, Telegram или мобильной сети.

## Безопасность

- Используйте отдельный токен BotFather и только доверенные числовые Telegram ID.
- Храните `.env` с правами `0600`.
- Никогда не добавляйте в GitHub базы, резервные копии, конфиги, UUID, VLESS-ссылки и приватные ключи.
- Перед `--apply` проверяйте список управляемых inbound: их `settings.clients` заменяется данными реестра.
- До production проверьте backup, Xray-валидацию, рестарт и восстановление на отдельной VM.
- Не обещайте универсальную работу через операторов РФ: тестировать каждый профиль нужно на целевом устройстве и сети.
