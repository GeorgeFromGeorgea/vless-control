# VLESS Control

VLESS Control — проект для установки Xray и управления VLESS-пользователями через закрытый Telegram-бот. Установщик ставит приложение и Xray, но для подключения нужны параметры сервера и сетевые настройки. Доступность через конкретного провайдера или мобильного оператора не гарантируется.

## Перед установкой подготовьте

1. VPS с чистой Ubuntu Server 22.04/24.04 или Debian 12, доступом `root`/`sudo` и интернетом.
2. Telegram-бота: в Telegram откройте `@BotFather`, отправьте `/newbot` и сохраните токен. Не публикуйте его.
3. Числовой Telegram ID администратора (не `@username`). Узнайте его через доверенный инструмент или существующую админ-панель.
4. Для REALITY — доменное имя для SNI. Это домен, используемый как маскировка TLS; он не обязан указывать на ваш VPS.
5. Проверьте у хостинга доступность выбранного TCP-порта. По умолчанию предлагается 443. Инсталлятор не может проверить фильтрацию у внешнего оператора.

Рекомендуется чистый сервер. Установщик откажется заменять существующие файлы без явного `--replace-existing` и подтверждения. Xray и бот не запускаются автоматически.

## Установка одной командой

На сервере выполните:

```bash
git clone https://github.com/GeorgeFromGeorgea/vless-control.git
cd vless-control
sudo ./install.sh
```

Установщик задаст вопросы, токен запросит скрытым вводом, установит зависимости и Xray из официального релиза с проверкой SHA-256, затем создаст `.env` с правами `600`, unit-файлы и первый VLESS/REALITY inbound, проверив конфигурацию через `xray run -test`. Параметры путей и порта можно принять клавишей Enter либо изменить. Для SNI при запросе `REALITY SNI hostname [www.cloudflare.com]` можно просто нажать Enter — это подставит `www.cloudflare.com`. Если указываете вручную, вводите только доменное имя, например `www.cloudflare.com`, без `https://`, порта или пути. SNI — имя TLS-сайта, под которое маскируется REALITY; адрес сервера в клиентской ссылке при этом остаётся адресом вашего VPS.

Если установщик сообщает о занятом порте или существующем Xray — остановитесь и выясните, чем управляется сервер. Не используйте `--replace-existing`, пока не создали и не проверили резервную копию.

После успешной проверки предложит отдельным подтверждением включить и запустить службы. Если вы подтвердите, Xray и бот будут запущены; если ответите иначе — останутся выключенными.

## После запуска

1. Откройте личный чат с ботом и отправьте `/start`. Доступ есть только у ID из `TELEGRAM_ADMIN_IDS`.
2. Создайте профиль с тем же `tag`, что у созданного inbound; адрес/порт/SNI/public key/short ID должны соответствовать конфигурации.
3. Создайте пользователя, назначьте профиль и получите VLESS-ссылку в приватном чате администратора.
4. Ссылки, UUID, `.env` и Xray-конфиг — секреты. Не пересылайте их в публичные чаты и не храните в Git.

## Как использовать VLESS-ключ

1. В боте создайте пользователя, назначьте ему профиль и получите для него VLESS-ссылку. Передавайте ссылку этому пользователю лично: она содержит уникальный UUID и даёт доступ к серверу.
2. На устройстве установите VLESS-клиент, поддерживающий REALITY (например, v2rayNG на Android или Shadowrocket на iOS; доступность приложений зависит от региона и магазина).
3. Импортируйте ключ в клиент: обычно достаточно скопировать `vless://…` ссылку и выбрать в приложении «Импорт из буфера обмена» / «Добавить из буфера обмена». Если клиент поддерживает QR-импорт — можно отсканировать QR-код, созданный из этой ссылки.
4. Выберите добавленный профиль и подключитесь. Для REALITY параметры ссылки должны соответствовать серверному профилю; вручную менять UUID, адрес, порт, SNI, public key, short ID или transport не нужно.
5. Если подключение не работает, проверьте, что Xray запущен, TCP-порт разрешён в firewall VPS и панели хостинга, а адрес/порт и параметры REALITY совпадают. Проверьте подключение и через Wi-Fi, и через мобильную сеть: доступность зависит от сети и оператора.

**Безопасность и отзыв доступа:** не публикуйте ключ в чатах/скриншотах и не отправляйте его посторонним. Считайте его паролем. При утечке деактивируйте пользователя в боте и примените синхронизацию изменений к Xray; деактивация только в реестре сама по себе не гарантирует немедленный отзыв уже работающего ключа. После отзыва создайте пользователю новый ключ.

## Возможности и ограничения

- Реестр пользователей/профилей, индивидуальные UUID, назначение профилей и выдача ссылок администратору.
- Telegram-панель с пошаговым созданием профиля и подтверждением деактивации пользователя.
- Генерация/валидация Xray-конфигурации и синхронизация клиентов с существующими inbound: по умолчанию dry-run, применение требует `--apply`.
- Первый inbound VLESS/REALITY создаётся автоматически; клиентскую запись нужно добавить после запуска бота.
- Установщик не настраивает автоматически DNS, firewall/security group, TLS-сертификат или доступность порта извне. Проверка кода не гарантирует подключение через конкретную мобильную сеть.

## Диагностика и отключение

```bash
sudo systemctl status xray --no-pager
sudo systemctl status vless-control --no-pager
sudo journalctl -u xray -n 100 --no-pager
sudo journalctl -u vless-control -n 100 --no-pager
```

Остановить службы и отключить автозапуск:

```bash
sudo systemctl disable --now vless-control
sudo systemctl disable --now xray
```
